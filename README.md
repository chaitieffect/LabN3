# Лабораторная работа №3. Календарь задач

## Цель работы

Разработать программу для создания и управления календарём задач с рабочим временем с 09:00 до 21:00. Программа должна поддерживать добавление, просмотр, поиск и удаление задач, а также работу со свободными временными промежутками.

## Математическая модель

Для упрощения вычислений время представляется целым количеством минут от начала суток:

- 09:00 соответствует 540 минутам;
- 21:00 соответствует 1260 минутам.

Каждая задача задаётся тройкой `T = (s, e, name)`, где `s` — время начала, `e` — время окончания, `name` — название. Продолжительность задачи равна `d = e - s`.

Рабочий день задаётся промежутком `[540, 1260]`. Для добавления задачи должны выполняться условия:

1. `540 <= s < 1260`;
2. `d > 0`;
3. `e = s + d <= 1260`;
4. название задачи не должно быть пустым.

Две задачи `A` и `B` пересекаются, если одновременно выполняются условия `A.s < B.e` и `A.e > B.s`. Поэтому задачи, у которых конец одной совпадает с началом другой, не считаются пересекающимися. Это позволяет ставить задачи подряд без свободной минуты между ними.

Временные промежутки для поиска и вырезания рассматриваются как полуоткрытые интервалы `[a, b)`: начало входит в промежуток, конец не входит. Для удаления задач по времени начала используются обе границы промежутка.

При удалении пересекающегося промежутка `[a, b)` из задачи `[s, e)` остаются следующие части:

- если `s < a`, сохраняется левая часть `[s, a)`;
- если `e > b`, сохраняется правая часть `[b, e)`.

Если промежуток находится внутри задачи, остаются две отдельные задачи с прежним названием. Если задача целиком находится внутри удаляемого промежутка, она удаляется полностью.

Для поиска первого свободного промежутка программа начинает проверку с 09:00 и последовательно рассматривает задачи в хронологическом порядке. Если разница между началом очередной задачи и текущим концом занятого времени не меньше нужной продолжительности, новая задача размещается в найденном промежутке. Иначе проверка продолжается после окончания очередной задачи.

## Описание классов

### `Task`

Класс описывает одну задачу календаря. Он хранит время начала, время окончания и название задачи. Метод `getDuration()` вычисляет продолжительность, а `formatTime()` переводит количество минут в формат `чч:мм`. Класс нужен, чтобы объединить данные одной задачи и не хранить их отдельно в разных списках.

### `TaskCalendar`

Основной класс логики календаря. Он хранит список объектов `Task` и отвечает за все операции с ним:

- `addTask()` — добавляет задачу, если время корректно и нет пересечений;
- `getTasks()` — возвращает список задач в хронологическом порядке;
- `getLongestTask()` — находит первую по времени задачу максимальной продолжительности;
- `getTasksInPeriod()` — находит задачи, пересекающие заданный промежуток;
- `getCompletedBefore()` — находит задачи, которые закончились не позже указанного времени;
- `removeTask()` — удаляет задачу по её текущему номеру в списке;
- `removeStartingInPeriod()` — удаляет задачи, начало которых находится в заданном промежутке;
- `removeIntersectingPeriod()` — удаляет или обрезает задачи, пересекающие промежуток;
- `removeShortestTasks()` — удаляет все задачи минимальной продолжительности;
- `addInFirstFreeSlot()` — добавляет задачу в первый свободный промежуток подходящей длины.

Этот класс отделяет правила работы календаря от пользовательского ввода и вывода. После изменений задачи остаются отсортированными по времени начала.

### `Main`

Класс пользовательского интерфейса. Он выводит меню, получает команды и данные с клавиатуры, проверяет формат времени и вызывает методы `TaskCalendar`. Здесь находятся только ввод, вывод и обработка выбора пользователя; правила управления задачами находятся в `TaskCalendar`.

### `CalendarTests`

Отдельный класс для автоматической проверки программы. Он создаёт тестовые календари, вызывает методы `TaskCalendar` и проверяет полученные результаты. Для этого используется метод `check()`, который выводит `[OK]` при успешной проверке и `[ОШИБКА]` при неуспешной. В конце выводится количество успешных проверок и ошибок.

## Тестирование

Тесты запускаются отдельно от пользовательского меню. Проверяются следующие ситуации:

| Проверка | Что проверяется | Ожидаемый результат |
|---|---|---|
| Добавление и сортировка | Добавление задач в разном порядке | Задачи хранятся по времени начала |
| Пересечения и границы дня | Добавление пересекающейся задачи и задачи, выходящей за 21:00 | Обе задачи отклоняются |
| Самая длинная задача | Две задачи имеют одинаковую максимальную длительность | Возвращается первая по времени |
| Поиск на промежутке | Задачи пересекают промежуток разными сторонами | Найдены обе задачи |
| Полное покрытие промежутка | Одна задача полностью содержит искомый промежуток | Задача найдена |
| Завершённые задачи | Окончание задачи совпадает с заданным временем | Такая задача считается завершённой |
| Удаление по номеру | Удаление существующего и несуществующего номера | Удаляется только задача с допустимым номером |
| Удаление по времени начала | Начало задачи совпадает с границами заданного промежутка | Обе задачи удаляются |
| Обрезка промежутка | Удаляемый промежуток находится внутри одной задачи | Остаются две части исходной задачи |
| Удаление коротких задач | Несколько задач имеют минимальную длительность | Удаляются все задачи с этой длительностью |
| Первый свободный промежуток | Между задачами есть подходящий интервал | Новая задача занимает самый ранний подходящий интервал |
| Нет свободного промежутка | Рабочий день занят полностью | Новая задача не добавляется |

## Запуск программы

Для компиляции и запуска из папки с файлами используйте команды:

```bash
javac -encoding UTF-8 Task.java TaskCalendar.java Main.java CalendarTests.java
java Main
```

Для запуска автоматических тестов:

```bash
java CalendarTests
```

Тесты завершают работу с ошибкой, если хотя бы одна проверка не пройдена. Всего выполняется 13 проверок. В тестовом классе используются, в частности, следующие данные:

- для проверки сортировки добавляются задачи в 12:00 и 09:00; ожидается, что задача на 09:00 будет первой;
- для проверки поиска самой длинной задачи добавляются задачи длительностью 30, 90 и 90 минут; ожидается первая из двух задач по 90 минут;
- для поиска на промежутке `[09:30, 11:30)` добавляются задачи `[09:00, 10:00)`, `[11:00, 12:00)` и `[13:00, 14:00)`; ожидаются первые две;
- для проверки завершённых задач при времени 11:00 добавляются задачи `[09:00, 10:00)`, `[10:00, 11:00)` и `[11:00, 12:00)`; ожидаются первые две;
- для проверки обрезки из задачи `[09:00, 15:00)` удаляется промежуток `[11:00, 13:00)`; ожидаются две части: `[09:00, 11:00)` и `[13:00, 15:00)`;
- для проверки первого свободного промежутка добавляются задачи `[09:00, 10:00)` и `[10:30, 12:00)`, затем размещается задача длительностью 20 минут; ожидаемый интервал — `[10:00, 10:20)`.

Остальные проверки охватывают запрет пересечений, выход за пределы рабочего дня, удаление по номеру, удаление по времени начала, удаление всех задач минимальной длительности и ситуацию, когда свободного промежутка нет.
